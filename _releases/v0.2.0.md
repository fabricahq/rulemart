## ✨ New Features

### Find rules by technology, by practice, or by searching

Rulemart now finds the rule you need across every vetted library, not one library at a time.

- The home page leads with search, and a tile for each technology and practice, sorted by how many rules it holds. `/browse/techs` and `/browse/practices` list every group, and each group has its own page, canonical or not.
- A group's page and search results share one list beside filters for library, impact, and stars, plus kind on search. Sort by best match, most starred, or newest. Signed in, My libraries keeps only the libraries you, your organizations, and your projects use.
- Search matches titles, reading guidance, rule text, group names, and rule IDs. It finds retired rules too, listed last.
- `/libraries` lists the vetted libraries, each owner of one has a page listing theirs, and `/faq` answers common questions.

(#20, #30, #36, #40)

### Star the rules you rely on

Signed in, you can star any current rule of a vetted library. Every rule row shows its count, lists can sort and filter by it, and your dashboard's Starred rules tab lists yours. A star follows its rule through renames and replacements. (#24, #34, #35)

### A cart that checks out to a prompt or to commands

Collect rules and whole groups from any library in a cart that lives in your browser, with no account needed; Rulemart keeps none of it. Checkout sets up a project two ways: one prompt to paste into a coding agent, or the `code-rules` commands to run yourself, which need Code Rules 0.2.0 or later. Signed in, checkout offers your projects that already use Code Rules and adds to them.

Checkout pins nothing by default, so rules follow their newest versions, and the Commands tab shows how to pin a release with `--ref`. An unvetted library is always pinned to the commit Rulemart saw, and the agent is asked to review its rules before following them. (#25, #37, #39)

### Library and rule pages, with every version

- A library's page has three tabs. Groups lets you tick groups and add them to the cart. All rules shows retired rules in place when you ask. Library releases lists each release and compares any two.
- A rule's page shows its tags, impact, publisher, license, and file. Its Versions tab compares any two versions, word by word or line by line.
- A retired rule keeps its page, with its last text and the rules that replaced it.

(#28, #38)

### Rule assets

The supporting files Code Rules copies with a rule now have their own pages. Images show inline, text and Markdown render on the page, and larger or binary files link to GitHub. Links in a rule's text lead to these pages. (#38)

### Sign in with GitHub, and a dashboard

Sign in with GitHub to star rules and use your dashboard at `/me`. It lists the libraries you and your organizations publish, with their star totals, and your projects that use Code Rules, with how many rule updates each is waiting for. To include private repositories, install the GitHub App "Rulemart by Fabrica" from `/me/private`; Rulemart shows what it reads there only to you. The Account section signs you out everywhere, or deletes your account and everything Rulemart keeps for it. (#22, #39)

### Add a library

Anyone signed in can add a public Code Rules library at `/me/add`: pick one of your own or your organizations' repositories, or paste a GitHub URL. A checklist follows Rulemart's check of the library, and `/me/listings` lists the libraries you added. An added library is unvetted until Fabrica vets it. (#23, #39)

### Vetting as an opt-in

Lists, groups, and search show only vetted libraries until a visitor chooses **Include unvetted libraries**. An unvetted library's pages warn readers to review its rules carefully, and ask search engines not to index them. The [Library vetting](https://rulemart.fabricahq.com/about/vetting) page explains what vetting means, how to get a library vetted, and how to report one. (#23, #36, #40, #42)

### About, privacy, and feedback

- [About](https://rulemart.fabricahq.com/about) explains why agents need granular rules, and how Code Rules and Rulemart provide them.
- [Privacy](https://rulemart.fabricahq.com/privacy) says what Rulemart keeps and reads, and for how long: the sealed GitHub token, what it reads of a GitHub account and its organizations, the browser cart, stars, and analytics. Privacy questions go to legal@fabricahq.com.
- [Feedback](https://rulemart.fabricahq.com/feedback) opens a prefilled GitHub issue for each topic, and each library links to a form to report it. Security reports go to security@fabricahq.com.

(#26, #30, #40, #42)

### Analytics

When the operator sets a Cloudflare Web Analytics site token, every page counts page views, signed in or not. Without the token, Rulemart loads no analytics, and the privacy page says so. (#26, #40)

### Links for search engines and sharing

Each page names its canonical address on `rulemart.fabricahq.com`, `/sitemap.xml` lists the vetted libraries' pages, and `robots.txt` keeps crawlers off account, cart, sign-in, and search pages. A shared link shows a card with Rulemart's image. (#19, #26, #40)

## ⬆️ Improvements

- Rulemart has its own mark, on the home page, the browser tab, a phone's home screen, and shared links. (#33)
- Every response now sends HSTS, a Permissions-Policy, and a Cross-Origin-Opener-Policy, beside the existing security headers. (#26)
- Browsers check public pages again on each visit, while CloudFront still keeps them for a minute, so a change shows within a minute. (#24)
- A rule's reading guidance renders as Markdown. (#20)

## 🐛 Squashed Bugs

- An address holding a NUL byte or invalid UTF-8 answered with a 503 error; it now answers 404. (#24)
- A library's About panel scrolled sideways when a file name was long; it now wraps. (#20)
