## ✨ New Features

### Projects that use trailguide's lockfile show their updates

The dashboard now reads a project's sources and rule versions from `.trailguide/lock.json`, which trailguide 0.7.0 and later write instead of a provenance file. Before, a project that moved to the lockfile showed the release it had before the move. Update counts also leave out rules the project excludes, replaces, or pins, since an update wouldn't change them. A project without a lockfile still reads as before. (#67)

### The add picker finds libraries in `.trailguide/`

The dashboard and the add page now find a library whose manifest is the library section of `.trailguide/config.yaml`, as well as one with `rule-library.yaml` at its root. Before, a library that moved into `.trailguide/` dropped out of the picker. (#63)

## ⬆️ Improvements

### Rulemart says trailguide

Rulemart's pages, help, checkout, and error messages now call the product trailguide, and checkout tells agents to read `.trailguide/_managed/generated/RULES.md`, where trailguide 0.8.0 keeps it. (#66, #68)

## 🐛 Squashed Bugs

### Fabrica's public library updates again

Since `release/4`, public-library's manifest declares skill levels, and `release/5` declares the library schema version that trailguide 0.8.0 requires. Rulemart rejected both, so the worker's hourly job for the library failed, retried, and set off the jobs queue's alarms. Rulemart now reads libraries as trailguide itself does, so those releases ingest. A library whose schema version Rulemart can't read tells its lister why, and the catalog keeps the releases it already has. (#65, #66)

This release adds no migrations.
